# ITSM V2 · 运营诊断工作台

基于用户提供的 ITSM_V2_context.md 独立重建。经用户确认，当前采用独立 Next.js 14 + Ant Design 5 工程；**尚未接入公司 CAgent 脚手架**，没有使用或修改 V1。

## 运行

需要 Node.js 22.18+（当前验证环境 Node 24）。

```sh
npm ci
npm run build
npm start
```

打开 http://127.0.0.1:3000。开发运行 `npm run dev`。默认仅监听本机，启动脚本关闭 Next.js 非必要遥测。

## 功能

- 运营总览：有效样本指标、周趋势、工厂/故障结构、人员差异。
- 人员分析：按工号区分人员、全团队/同工厂/同类型/同故障对标与指标导出。
- 人员诊断：响应/处理/逾期差异、首次观察到差异的周、最近连续周数、复杂工单占比、场景下钻。
- 趋势与风险：创建周队列趋势，确认数据完整性后提供未来30天工作量参考和最后两周留出回测。
- 全局日期、工厂、类型、一级/三级故障、原始状态、停机/VIP/影响基地/逾期筛选；模糊搜索、精确编码、图表交叉筛选。
- 工单明细抽屉、CSV 导出、诊断文本导出、数据质量报告。

## Excel 导入

支持 `.xlsx`，最大 20MB、50,000 数据行、300 列。`.xls` 请先另存为 `.xlsx`。可选择工作表、表头行（前20行）、手动映射字段。一个原始列只能映射一个业务字段；工单ID或编码至少映射一个。重复 ID 在用户明确选择保留首次行后才允许导入。

数字小时字段优先，其次中文显示时长，再按已知起止时间推导。支持中文括号、`姓名（工号）`、`Y/N`、`1/0`、`5分（满分）` 等已观察到的样本格式。数字字段本身无效时不拿其他字段掩盖问题。

Excel 日期按业务墙上时间处理，支持1900/1904日期系统；文本日期支持 `YYYY-MM-DD` / `YYYY/MM/DD` 和时分秒，不擅自猜测地区格式或时区偏移。公式单元格不执行也不采信缓存；请先复制并粘贴为值。仅映射纯文本正文，HTML不渲染。

数据只驻留本页面的浏览器内存，不上传服务端、不写数据库、不存 localStorage，刷新或清空会话即丢失。再次导入会替换原数据，不自动追加。导出只含分析相关字段，CSV 对可能执行的公式文本进行转义。

## 数据与口径限制

`imag/` 中只有7张手机截图，并非完整Excel。它们仅用于核对字段和值的形态，不能核验真实数据分布。演示数据为程序生成，不复制真实人员或工单。

- 当前处理人不等于历史实际经办人，不能直接作为人员绩效归因。
- 无评分字段则不展示评价指标；不预设所有文件都为五分制。
- 办结占比以有效办结时间为证据；完整状态字典待验证。
- 缺失值不是0或否；逾期率只用明确是/否的样本为分母。
- 参照排除本人和未分配人员。同类模式聚合个人涉及的类别，但未按复杂度校正，须查看场景分布。
- 全局筛选（包括搜索）同时作用于本人和参照。若搜索仅命中某个人，可能没有参照，此时显示不可比较。
- “高于参照”是描述性差异，没有统计显著性或不合格的含义。
- 预测需用户确认连续完整覆盖，至少8个完整周是待数据验证的工程策略；同星期历史最小/最大是观测范围，不是置信区间。回测不优于日均基线会明确提示。
- SLA、完整状态字典、评价尺度、显著性和最小样本门槛仍需真实数据及业务确认。未引入综合健康度、固定权重或旧线性回归。

## 结构与验证

`src/domain/`：导入规范化、筛选、指标、对标、趋势、预测、CSV（无框架核心）。

`src/lib/workbook.ts`：客户端按需加载 ExcelJS、文件边界、工作表提取。

`src/components/`：AntD 界面、原生SVG图表、导入确认和证据抽屉。

```sh
npm test
npm run typecheck
npm run build
npm run test:e2e
```

端到端测试使用本机 Chrome，自动启动生产服务（先构建），生成的截图在 `test-results/`。测试使用自建合成 XLSX，不向外部传输工单。产品设计、指标依据及待验证项见 `docs/product-design.md`。
