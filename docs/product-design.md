# ITSM V2 产品与分析设计

## 1. 产品目标与用户任务

服务运营负责人从整体发现异常，定位到人员、工厂或类别，理解指标差异及工单结构，再查看具体工单证据；处理人查看自己的负载和时效变化。分析描述已发生的差异，不据此直接判定人员能力或因果。

用户任务：导入并验证 Excel → 选择一致的分析范围 → 查看整体与分布 → 识别高于/低于基准的指标 → 进入人员诊断 → 缩小到时间、工厂、类型或故障 → 查看/导出证据 → 评估未来一个月的工作量参考。

## 2. 数据契约

- 所有数据仅在当前浏览器内存中使用，刷新即清空，不发送到服务端，不使用数据库或 localStorage 保存工单。
- 支持选择工作表、映射字段、预览质量报告再导入。字段映射来自真实表头，不凭位置猜测。
- 工单编码/ID 至少一个用于标识；缺失标识的行不进入分析，保留行号与原因。重复标识不静默相加：报告并要求处理策略。
- 工号优先作为人员标识；只有姓名时明确提示同名可能混淆。未分配人员单独显示，不能自动归到任何人。
- 空值、非法数值、负时长、无效日期、未知布尔值都保持未知。保留数据质量计数；0 小时为合法值。
- 日期按 Excel 业务墙上时间解析；不依赖运行机器的时区。Excel 日期系统（1900/1904）由工作簿元数据决定。日期筛选默认基于创建日期、起止日均包含；日期无效行不满足日期范围。
- 数字小时字段优先；缺失时仅按明确定义的起止时间推导。响应时间：首次接收减创建；处理时间：办结减接收。流转时长无确定公式时不推导。
- 有效结束时间早于开始时间视为冲突，不作为完成/时效证据。
- 原始 HTML 绝不执行；工单明细优先纯文本。默认不导出手机号、群邀请链接、会话标识等非分析字段。

## 3. 指标口径

| 指标         | 口径                                                   | 缺失/限制                                    |
| ------------ | ------------------------------------------------------ | -------------------------------------------- |
| 工单量       | 当前筛选范围去重后的工单数                             | 按导出时当前处理人归属                       |
| 已办结占比   | 有有效办结时间的工单 / 范围内全部工单                  | 不是 SLA 达成率；状态码映射待核验            |
| 响应时长     | 有效非负响应小时的中位数、P90、样本数                  | 不以缺失补 0                                 |
| 处理时长     | 有效非负办结-接收小时的中位数、P90、样本数             | 不推断工作时间日历                           |
| 逾期率       | 明确“是”的工单 / 明确是或否的工单                      | 同时显示已知覆盖率，不从时长编造逾期         |
| 评价均值     | 有效数字评分的算术均值、有效样本数                     | 不假设满分、及格线或正负方向；无字段则不展示 |
| 评价覆盖     | 有效数字评分 / 全部工单                                | 未评价不等于差评                             |
| 特殊工单占比 | 停机、VIP、影响基地分别计算已知样本占比                | 仅解释结构，不加复杂度权重                   |
| 趋势         | 按创建日期分桶，展示量、响应中位数、处理中位数、逾期率 | 同一创建队列；不能冒充各日完成吞吐量         |

所有汇总显示有效分母。没有分母显示“暂无有效样本”。跨人员比较默认保留全局时间及分类筛选；个人与其他人员比较时排除本人，避免自身影响基准。

## 4. 对标与诊断

模式：全团队、同工厂、同类型、同一级故障。后面三种模式按个人工单所含分层寻找其他人员同层工单，同时展示基准样本量与结构差异；不声称已消除工作难度差异。

先提供描述性提示：“处理中位数比参照高 4.2 小时（+28%），本人 n=30，参照 n=120”。没有经过数据验证的统计阈值时不使用“显著异常”“不合格”等定性结论。

诊断页面包括：个人负载与有效覆盖、指标与参照差异、按周差异（首次观察到高于参照的周和连续周数）、工厂/类型/故障分布、特殊工单占比、原始工单明细。样本为零时展示无法比较。

问题集中度：展示每类工单数、该类处理中位数及同类其他人员的中位数；点击进入明细。优先列出有可比样本且差值较大的类别；不把量大直接当作表现差。

## 5. 趋势与未来一个月

- 描述历史趋势与样本数；不计算虚构风险分。
- 工作量参考采用星期季节性基线：按历史完整周，同一星期几的平均工单量预测随后 30 日；显示同星期几观测范围，不称为概率置信区间。
- 预测只在用户确认 Excel 覆盖连续完整日期（含零工单日）后启用。默认不能把缺少日期当零。
- 至少 8 个完整周为初版模型可计算条件（工程策略，待真实数据回测验证，不是业务阈值）。用最后两个完整周留出验证，对比简单日均基线，显示 MAE。
- 回测无改进则明确提示参考价值不足；可展示结果但不称可靠预测。
- 不外推未来个人评分、处理时长或确定逾期风险。招聘、调岗、业务增长等不在模型中。
- 未来范围锚定已确认数据截止日，非系统当前日期。

## 6. 信息架构与交互

采用顶部导航和横向筛选带，左侧留给内容，不采用旧 Sidebar。

1. 运营总览：数据范围、关键指标条、工作量趋势、工厂与故障结构、需关注的人员差异、工单证据。
2. 人员分析：可排序可检索人员表、指标对标、进入诊断。
3. 人员诊断：人员选择、对标模式、差异解释、时间与类别拆解、工单证据。
4. 趋势与风险：人员可选、三个历史指标趋势、季节性工作量参考、回测与限制。

筛选：创建时间、工厂、工单类型、一级/三级故障、原始状态、停机、VIP、影响基地、逾期；全文查工单编码/标题/正文/人员，支持精确编码模式。

Cross Filter：点击工厂条形图、分类条形图或趋势日期，更新同一全局筛选状态；筛选条件展示可移除标签；全局重置不会丢失导入数据。点击人员进入个人诊断，不把个人筛选混入团队基准。异常时间和类别可继续过滤到具体工单。

导出：当前范围工单 CSV、人员指标 CSV、诊断摘要，附筛选范围与口径。表格型导出处理公式注入。

## 7. 视觉方向

工业运营工作台：深墨绿标题、暖白底、细分隔线，松柏绿为交互色、琥珀色标记待关注差异。以大字号运营数字、宽幅趋势和紧凑证据表组织页面。强调“范围”“基准”“样本”，不过度使用卡片或装饰图。所有图形提供按钮或表格等可键盘操作的路径；小屏筛选折行、表格横向滚动。

## 8. 技术与验收

目标 CAgent / Next.js 14 App Router / React 18 / AntD 5。分析核心为无框架 TypeScript 纯函数，UI 为客户端交互，Excel 解析只在客户端发生。数据量上限作为内存保护明确告知，不能静默截断。

验收覆盖：空数据、无评价、同名不同工号、未知布尔值、0 时长、日期系统、重复 ID、负时长、全局联动、个人不污染基准、零分母、筛选后导出、预测覆盖确认、稀疏样本及回测、构建成功。

待数据验证：状态码字典、评价尺度与方向、同类可比性、人员归属、SLA、样本量门槛、统计异常阈值、季节性假设、真实 Excel 性能。
